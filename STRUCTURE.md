## Як влаштована теорія (prep.html)

`prep.html` — згенерований файл. Вміст усіх тем живе у `generator/prep_data_*.js`.
Кожна тема — обʼєкт із такими полями:

```js
{
  p: "P0",                    // пріоритет: P0 (критично) / P1 / P2
  name: "Назва теми",         // видима назва; за нею шукаються гілки в Discussions
  what: ["абзац", "абзац"],   // блок «Що це і як працює»
  problem: "один абзац",      // блок «Яку проблему вирішує»
  where: ["пункт", ...],      // блок «Де використовується на практиці»
  code: ["рядок коду", ...],  // блок «Приклад» (масив рядків; можна [] — блок зникне)
  traps: ["пункт", ...],      // блок «Пастки та типові помилки»
  also: ["swift-14", ...],    // необовʼязково: id сусідніх тем, що частково
                              // перекриваються — рендериться рядком «Поряд:»
  sections: [                 // необовʼязково: довгий розбір по кроках.
    { title, text, code }     // Тема з sections отримує бейдж 🪜 і НЕ показує
  ],                          // блок «Приклад» (code теми ігнорується)
  qs: [                       // блок «Контрольні питання»
    { q: "питання",
      a: ["абзац", "абзац"],  // еталонна відповідь (спойлер під питанням)
      code: ["рядок", ...] }, // необовʼязково
    "питання без відповіді",  // теж припустимо
  ],
}
```

### Два жанри тем

Теми без `sections` — конспект на 15 хвилин перед співбесідою (шість блоків).
Теми з `sections` — довгий розбір по кроках для першого знайомства; на сторінці вони
позначені бейджем 🪜. Не зливай ці жанри в одній темі: якщо матеріал розростається,
краще зробити окрему тему з `sections` і звʼязати їх через `also`.

### Формат еталонної відповіді (`a`)

Це не конспект, а те, що кажуть уголос на співбесіді за 1–2 хвилини: 1–3 абзаци до ~55 слів
кожен. Перший — пряма суть, другий — механіка або наслідок, третій — пастка чи практика
(симптом бага, а не загальні слова). `code` — лише коли питання просить код або без нього
відповідь неповна. Ті самі відповіді показуються і в mock.html, тому вони мусять бути
самодостатніми: без «див. тему вище».

### Додати нову тему

1. Відкрий потрібний `generator/prep_data_*.js`
2. Додай обʼєкт теми **В КІНЕЦЬ масиву `topics`** (перед закривними `],\n};`)
3. Онови число в `title` (наприклад `"SWIFT — 21 тема"`) і кількість тем у `index.html`
4. Перегенеруй і закоміть (див. «Робочий цикл» нижче)

⚠️ **Чому тільки в кінець:** id тем — порядкові (`swift-0`, `swift-1`…). Вставка
в середину зсуне id усіх наступних тем — поламаються якірні посилання з нотаток
у Discussions, збережений прогрес галочок і збережені оцінки в мок-співбесіді
(її ключі — `<id-теми>:<номер-питання>`).

### Змінити наявну тему

Просто редагуй її поля у `prep_data_*.js` і перегенеруй. Назву (`name`) краще
не міняти без потреби — за нею привʼязані гілки нотаток у Discussions.

## Інші сторінки

- **index.html** — статичні картки. Додаєш сторінку сайту → додай картку тут.
- **trainer.html** — самодостатній файл із завданнями (розмітка + стилі + JS).
  Завдання додаються редагуванням HTML за зразком сусідніх карток.
- **mock.html** — генерується з тих самих даних, що й теорія: беруться всі `qs` усіх тем.
  Логіка сторінки живе у `generator/gen_mock_html.js`, редагувати треба там.
- **interview.html** — розмовна частина: розповідь про себе, пʼять STAR-історій, system design
  задачі, питання до компанії, англійські формулювання, розмова про вилку. Вміст —
  `generator/interview_data.js` (звичайний JS-обʼєкт), розмітка — `generator/gen_interview_html.js`.
  Прогрес галочок: ключ `ios-prep-interview-v1`.

## Як працюють інтерактивні штуки

- **Прогрес (галочки)** — localStorage браузера, ключі: `ios-prep-deep-v1` (теми),
  `ios-prep-mock-v1` (оцінки й час у мок-співбесіді), тренажер має свій. Прогрес живе
  на домені сайту в конкретному браузері; при зміні домену — обнуляється.
- **Мок-співбесіда** — питання по одному під таймер, самооцінка «знав / плавав / не знав».
  Режим «розумний» ставить першими ті, де ти плавав або яких ще не питали.
- **Коментарі до тем** — giscus: кнопка «💬 Показати коментарі» вантажить віджет,
  привʼязка гілки — за назвою теми (data-term). Гілки зберігаються у
  GitHub Discussions репозиторію (категорія Announcements для віджета,
  General — для нотаток через 💬/🧵 у заголовку теми).
- **Картинки в нотатках** — через GitHub: відкрий гілку (🧵) і встав скріншот
  (Cmd+V) у коментар на github.com; на сайті він відобразиться.
- **Редагувати/видалити коментар** — клік на дату коментаря у віджеті →
  відкриється на GitHub → меню ··· → Edit / Delete.

## Деплой і якщо він упав

Сайт публікує GitHub Actions (workflow `static.yml`, Settings → Pages →
Source: GitHub Actions). Статус: https://github.com/Nazarzbs/iOSprep/actions

**Якщо деплой упав** («Deployment failed», «Multiple artifacts»): НЕ натискай
Re-run — зроби будь-який новий коміт (пробіл у README) і Push. Перезапуск
через Re-run створює дублікат артефакту і падає знову.
